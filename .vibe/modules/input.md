# Module: input
**Role:** Character file input — folder selection only (item 014), replacing the earlier per-kind file picker outright. `folder-entries.ts` gathers a folder picker's or a dropped folder's files into a flat `{file, relativePath}` list. `def-files-section.ts` does a narrow local read of a chosen `.def`'s own `[Files]` section, learning which `.air`/`.sff`/`.cns`/`.cmd` filenames it references (the WASM bridge's own `load` call needs all 4 required files' bytes at once, so it can't answer this on its own). `character-file-input.ts` finds the folder's `.def` candidate(s), resolves each referenced filename against the folder listing by basename (exact case, then case-insensitive; ambiguous if more than one match), reads the resolved bytes, and loads the character through the `wasm` module. `.zss` has no `[Files]`-section key of its own in the underlying library, so it's located by extension alone; more than one never blocks loading. `character-file-input-view.ts` renders the folder-picker + drag-and-drop UI, including the multi-`.def` candidate picker. The view subscribes to `onLocaleChange` internally (item 012): its static text and current status/error retranslate in place from the raw state already held, without re-reading a file or re-running the WASM bridge.
**Files:** `src/input/folder-entries.ts`, `src/input/def-files-section.ts`, `src/input/character-file-input.ts`, `src/input/character-file-input-view.ts`
**Exports:** `GatheredFile`, `FileEntryLike`, `DirectoryEntryLike`, `DirectoryReaderLike`, `EntryLike`, `DataTransferItemLike`, `collectFilesFromEntry(entry): Promise<GatheredFile[]>`, `filesFromDataTransferItems(items): Promise<GatheredFile[]>`, `filesFromWebkitDirectoryFiles(files): GatheredFile[]`, `DefFileReferences`, `parseDefFileReferences(defText): DefFileReferences`, `resolveDefCandidates(files): DefCandidateResolution`, `resolveReferencedFile(referencedPath, files): ReferenceResolution`, `resolveZssFile(files): ZssResolution`, `loadCharacterFromChosenDef(entry, files, options?): Promise<CharacterFolderLoadResult>`, `loadCharacterFromFolderFiles(files, options?): Promise<CharacterFolderLoadResult>`, `readFileAsBytes(file): Promise<Uint8Array>`, `REQUIRED_FILE_KINDS`, `OPTIONAL_FILE_KINDS`, `ALL_FILE_KINDS`, `EXTENSION_BY_KIND`, `FileKind`, `RequiredFileKind`, `OptionalFileKind`, `LoadedFileBytes`, `CharacterInputResult`, `CharacterFolderLoadResult`, `CharacterFileInputOptions`, `CharacterFileInputViewOptions`, `renderCharacterFileInput(root, options): void`
**Depends on:** `modules/wasm.md`, `modules/i18n.md`

**Sound file (item 017):** the `.def`'s `sound =` reference is resolved like the optional `.cmd` but never blocks the load: its bytes go to `loadCharacter` as `sndBytes`; a missing/ambiguous/unreadable file, or a wholly invalid `.snd` (the load is retried without it), is reported as `files.sndIssue` text instead of an error status. `files.snd` keeps the raw bytes when present.

**Robust loading (UX flow 002):** `loadCharacterFromChosenDef` takes an `AbortSignal` and an `onProgress` callback (named steps definition, files n/N, engine, open) and returns `cancelled` when aborted, so nothing is mounted late. A sprite, sound, command or script file the browser cannot read no longer fails the load: it is reported in `unreadable` (the engine gets the bundled blank `.sff` as stand-in for a missing sprite sheet); `.def`, `.air`, `.cns` stay fatal. `unsupportedSffVersion` rejects a sprite sheet whose header major version is not 1 or 2. The view shows the steps after 300 ms with Cancel, keeps the picker usable on any failure (Retry only for transient causes), announces a failure once through `onFailure`, and hands a version problem to its caller.
