# Module: problems
**Role:** The problem registry's building blocks (UX flow 002). A problem is a typed code plus parameters, localized when rendered, with the engine's raw text kept apart as `detail` (shown only behind "Show details"). Views of the same fact: `problem-view` (message, cause, next step, details), `problems-banner` (under the toolbar; collapsible, never dismissable), `dependency-cards` (a section whose file or the engine is unavailable shows a card with Replace file / Retry instead of its editor), `inline-error` (under the failed control, dismissable, reports to the registry), `preview-failure` + `preview-guard` (request token so only the latest preview answer paints; placeholder with Retry, last good frame dimmed). `engine-retry` allows one in-flight engine attempt. `replace-file` checks a replacement with the engine before one undoable command. `problem-issues` turns the `load`, `engine` and `action` sources into validation issues.
