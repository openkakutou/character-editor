# Module: save
**Role:** Save/Export (item 009): serializes the current in-memory character back out to downloadable files. `character-export.ts` is the DOM-free orchestration — decides which of `.def`/`.air`/`.cns`/`.cmd`/`.zss` belong in the bundle, calls the WASM bridge's `saveDef`/`saveAir`/`saveCns`/`saveCmd`, labels each result "unchanged"/"modified" against its original bytes, and blocks the whole export (with a precise reason) on a pending sprite edit or any `saveX` call's own error rather than ever offering a partial/stale bundle. `.act` palette files and `.sff` sprite pixel data are out of scope — see `.vibe/decisions/009`. `export-panel.ts` is the DOM layer: computes once on first render and again only on its own explicit "Refresh export" action, never live on every edit elsewhere — see `.vibe/decisions/010`.
**Files:** `src/save/character-export.ts`, `src/save/export-panel.ts`
**Exports:** `exportCharacterFiles(doc, options?): Promise<ExportResult>`, `describeSpriteEdit(edit): string`, `ExportFileKind`, `ExportedFile`, `ExportOptions`, `ExportResult`, `ExportBlockedReason`, `PendingSpriteEditsBlockedReason`, `SerializeErrorBlockedReason` (character-export.ts) — DOM-free logic; `renderExportPanel(root, options?): void`, `ExportPanelOptions` (export-panel.ts) — the DOM layer
**Depends on:** `modules/wasm.md` (`saveDef`/`saveAir`/`saveCns`/`saveCmd`, `CharacterInfoFields`), `modules/document.md` (`CharacterDocument`), `modules/sprites.md` (`SpriteEdit`), `modules/palettes.md` (reuses `defaultTriggerDownload`)
