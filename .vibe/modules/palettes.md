# Module: palettes
**Role:** The palette editor (backlog item 005): edit a 256-color palette's colors, start a new one (blank or duplicated), load/save it as a `.act` file, with a live-recolored sprite preview. Stores colors in semantic MUGEN index order, converting to/from `.act` file-byte order via one shared involution — see `.vibe/decisions/005-palette-model-semantic-index-order-shared-reversal.md`. Manages its own undo/redo (item 010): every local edit (color change, new blank, duplicate, upload) pushes a data-only command onto `history`'s shared `CommandStack` directly, rather than through a caller `onChange`; `renderPaletteEditor` returns a `PaletteEditorHandle` whose `refresh()` lets an external Undo/Redo click ask this screen to rebuild from the restored state, and the `onHistoryPush` option tells the caller a local push just happened so its own toolbar state can stay in sync. A normal edit's own DOM update stays fine-grained (never rebuilding the color picker mid-interaction); only `refresh()`'s external-trigger path does a full rebuild — see `.vibe/decisions/011`. Reads its own strings through `i18n.t()` and subscribes to `onLocaleChange` internally (item 012): retranslates its static chrome (upload label, New blank/Duplicate buttons) in place, then calls its own `renderBody()` — the same full-rebuild-from-current-data mechanism its external `refresh()` already uses — so a locale switch preserves the active palette, selected index, and preview sprite exactly as well as an Undo/Redo click already does.
