# Module: commands
**Role:** The command editor (item 008): view/edit an already-loaded character's `.cmd` commands (name, input sequence, timing overrides) and optionally map each one to a target combat state from `character.stateDefs`. Unlike every other editor screen, this one owns its own WASM call (`wasm.loadCmd`) rather than reading an already-parsed field off `CharacterData`, since `.cmd` isn't wired into that type at all — a missing or unparseable `.cmd` file degrades to a visible message plus a usable blank starting point. The command-to-state link is represented the way the real file format does it: a `ChangeState` controller inside the linked always-state, keyed by the command's name (see `.vibe/decisions/008-command-editor-state-link-and-validation-scope.md`). A row with a blank/duplicate name, blank input, or an unknown target state is excluded from the committed model entirely until fixed; loading already-invalid data never discards it.
**Files:** `src/commands/command-logic.ts`, `src/commands/command-editor.ts`
**Exports:** `emptyCommandFile(): CommandFile`, `validateCommandRow(name, input, targetStateText, otherNames, availableStateNumbers): CommandRowValidation`, `findLinkedStateNumber(states, commandName): number | null`, `setLinkedState(states, commandName, targetState): StateDef[]`, `renderCommandEditor(root, character, cmdBytes, options): void`, `CommandEditorOptions`
**Depends on:** `modules/wasm.md` (for `loadCmd`, `CommandFile`/`Command`/`StateDef`/`Controller`)
