# Module: document
**Role:** In-memory representation of the currently loaded character — the WASM-parsed data, every supplied file's raw bytes, a pending sprite-edit overlay (`spriteEdits`, item 004), and the command editor's latest committed `.cmd` model (`commandFile`, item 008) — the single place editor screens read from and write back to via shared patch/append helpers. Every genuine-edit mutator (`updateCharacterFields`, `addSpriteEdit`, `setCommandFile`) records an undo/redo entry on `history`'s shared `CommandStack` instead of mutating state directly (item 010); `seedCommandFile` mutates without recording one, for the command editor's own load-time seed which isn't a user edit. `updateCharacterFields` snapshots the character as a deep clone before/after each patch rather than a live reference, since some editors mutate a nested object in place before committing — see `.vibe/decisions/011-undo-redo-snapshot-strategy.md`.
**Files:** `src/document/character-document.ts`
**Exports:** `getCharacterDocument(): CharacterDocument | null`, `setCharacterDocument(doc: LoadedCharacter | null): void`, `updateCharacterFields(patch: Partial<CharacterData>): void`, `addSpriteEdit(edit: SpriteEdit): void`, `setCommandFile(commandFile: CommandFile): void`, `seedCommandFile(commandFile: CommandFile): void`, `resetCharacterDocumentForTests(): void`, `CharacterDocument`, `LoadedCharacter`
