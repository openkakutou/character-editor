# Module: i18n
**Role:** This app's own localization setup (backlog item 012): a thin wrapper around `@openkakutou/web-ui-kit`'s shared i18next integration layer, under this app's own namespace (`"character-editor"`) and its own `localStorage` key (`"character-editor-locale"`, not the shared default — every OpenKakutou app deploys on the same GitHub Pages origin). `en.json`/`fr.json` are the two message catalogs; every other module's DOM layer reads its own strings through `t(key, defaultValue, vars?)`, which returns the interpolated `defaultValue` verbatim whenever `initAppI18n` hasn't resolved yet (e.g. in a test), so a render is identical either way. `app` awaits `initAppI18n()` once at bootstrap, before the first render, then subscribes to `onLocaleChange` to retranslate the toolbar chrome and re-invoke the characteristics/state/animation editors' own existing render calls; every other screen with session-important state (file input, wizard, sprite browser, palette/command editors, export panel, shortcuts screen) subscribes internally instead, reformatting only its own already-shown text from a small stored description, never re-running the WASM call or file read that produced it. See `docs/architecture.md`'s "Data flow: switching locale" and `.vibe/decisions/015-i18n-integration-approach.md`.
**Files:** `src/i18n/i18n.ts`, `src/i18n/en.json`, `src/i18n/fr.json`
**Exports:** `NAMESPACE: string`, `STORAGE_KEY: string`, `initAppI18n(): Promise<I18nInstance>`, `getI18n(): I18nInstance | undefined`, `onLocaleChange(callback): () => void`, `t(key, defaultValue, vars?): string`
**Depends on:** `@openkakutou/web-ui-kit` (external — `initI18n`, `getI18n`, `onLocaleChange`, the shared i18next instance and `<wuik-locale-switcher>`)
