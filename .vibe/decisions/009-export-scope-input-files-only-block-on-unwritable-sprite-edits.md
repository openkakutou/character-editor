# Export scope: the loaded input file set only; blocked (not silently dropped) on unwritable sprite edits

**Context:** Backlog item 009 asks to serialize every edit from items 003-008 back out to downloadable files, format-preserving. Two of those items don't fit that literally: item 004's sprite pixel edits (add/replace/delete) have no WASM write path yet (`sff`'s WASM build only exposes `load`/`resolveSprites`, no encode/save — confirmed against `sff/cmd/wasm/main.go`, and `character`'s own WASM build only exposes `saveDef`/`saveAir`/`saveCns`/`saveCmd`/`saveZss`, nothing for sprites), and item 005's palette edits were never part of the character's loaded input file set in the first place (`.act` isn't one of the 4 required + 2 optional kinds `character-file-input.ts` accepts) — the palette editor already ships its own standalone "Save as .act" download, unrelated to what was originally loaded.

**Decision:** Export bundles exactly the file kinds the character input already accepts: `.def`/`.air`/`.cns` always, `.cmd` when the character had one originally or the user added at least one command, `.zss` when one was originally supplied (never edited, only passed through byte-for-byte — this app has no `.zss` editor). `.sff` is passed through unchanged only when no sprite edits are pending; when one or more are pending, Export is blocked outright with a clear per-edit reason (which sprite, which kind of edit) instead of silently exporting a `.sff` that doesn't reflect them, or exporting everything else while quietly dropping the sprite changes. Palette (`.act`) files stay out of this bundle entirely.

**Reason:** This keeps the exported bundle's meaning honest: every file in it is either byte-identical to what was loaded or reflects a real, complete edit this app can actually serialize — never a partial or silently-stale file. It also matches the acceptance criterion's own wording literally ("an edit that can't be safely serialized... blocks export with a clear error identifying the offending edit") — the sprite-edit case already fits that description exactly, with no special exception needed.

**Rejected alternatives:** Silently omitting `.sff` from the bundle while exporting everything else — rejected because a user could reasonably believe their sprite edits were included, discovering otherwise only by comparing the download against a real MUGEN/Ikemen engine. Re-deriving `.sff` bytes by hand in TypeScript, bypassing the missing WASM write path — rejected: sprite pixel encoding (palette-indexed PCX/RLE8/LZ5) is exactly the "don't reimplement the Go library" boundary this app's architecture already commits to (see this repo's own CLAUDE.md). Waiting on `sff`'s own WASM write path before shipping any export at all — rejected: it would block every other already-finished editor's work (003, 006, 007, 008) on an unrelated repo's roadmap, with no tracked timeline.
