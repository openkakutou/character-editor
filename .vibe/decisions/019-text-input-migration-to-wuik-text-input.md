# Migrate plain `<input>` text fields to `<wuik-text-input>`

**Context:** Backlog item 013 migrates every plain, token-styled `<input type="text">` stopgap (characteristics editor's scalar fields and dynamic list rows, the new-character wizard's Name field, the command editor's Name/Input-sequence fields) to `web-ui-kit`'s newly-shipped `<wuik-text-input>` (`@openkakutou/web-ui-kit@0.14.1`, bumped from the `^0.13.0` pin). The component owns its own label/input/error layout and invalid-state styling internally (shadow DOM), and exposes only a narrow attribute/event contract: `label`/`placeholder`/`required`/`value`/`disabled`/`error` attributes, `wuik-input` (fires live, every keystroke) and `wuik-change` (fires on the internal input's native `change`) events — no public `focus()` delegate (no `delegatesFocus`), no way to observe a bare, value-unchanged blur.

**Decision:**
- **Validation stays app-owned via the `error` attribute**, never the component's own built-in blur-gated required message: every migrated field keeps computing its own custom, translated message (`"{{label}} cannot be empty."`, duplicate-name detection, etc.) and drives the component's invalid state by setting/clearing `error` directly. The one exception is the characteristics editor's two dynamic lists (`stateFiles`/`palettes`), which have no per-row label to parameterize a custom message against — these rows set `required` and rely on the component's own generic default message instead, an accepted, minor behavior change from the pre-migration silent border-only cue (now shows "This field is required." text too).
- **`focusout` (composed + bubbling), not `blur` or `wuik-change`, drives "touched" gating.** `blur`/`focus` don't cross a shadow boundary at all (`composed: false`); `wuik-change` only fires when the value actually differs from focus-time, which would silently leave a row focused-then-abandoned without any edit showing no cue at all (worse than the pre-migration native-blur behavior it replaces). `focusout` is composed and retargets to the host, exactly reproducing the old native-`blur`-on-a-plain-`<input>` semantics — including the "left blank without ever typing" case.
- **A row/field reaching `<wuik-text-input>`'s shadow root directly for `.focus()`** (`el.shadowRoot?.querySelector("input")?.focus()`, guarded exactly like every other `<wuik-*>` method this app's test environment doesn't register): the component has no public focus proxy, so this is the only way to keep the pre-existing "focus the newly-added row" convenience (characteristics editor) and add the new "focus the Name field on a failed submit" one (wizard, a UI/UX-expert requirement). Confirmed working in a real browser; a future `web-ui-kit` version could regress it silently if its internal markup changes — worth raising upstream as a `focus()` delegate or `delegatesFocus: true`, but not blocking this migration.
- **Number-type fields are explicitly out of scope**: `command-editor.ts`'s Time/Buffer time/Target state stay plain native `<input type="number">` — `wuik-text-input` only renders `type="text"` internally, no numeric semantics to migrate to.
- **The wizard's Name field shows its "required" error inline on the field itself only**, not duplicated on the shared dialog-level error line (found redundant — both showing the exact same sentence — by real-browser runtime verification); the shared line stays reserved for a genuine post-submit, non-field failure (e.g. a bridge error).
- **A list row keeps no visible `label`**: `<wuik-text-input>` hides its entire internal `<label>` (required-marker included) when `label` is unset/empty, exactly preserving the pre-migration "the section heading already names the list, individual rows don't repeat it" design — confirmed by reading the component's own source, not assumed.

**Reason:** Preserves every screen's actual, already-thought-through validation UX (live-on-keystroke for Name, custom parameterized messages, duplicate-name re-validation across rows) rather than downgrading to the component's own generic, blur-only required check everywhere; `focusout` closes the one real gap (blur detection) the component's event contract would otherwise leave, without which the single most common blank-row scenario (added, never typed into, then left) would regress to no feedback at all.

**Rejected alternatives:**
- **Use the component's own built-in `required`+blur-gated message everywhere** (drop custom app-level validation entirely): rejected — loses parameterized field-name messages, duplicate-name detection, and the characteristics-editor Name field's deliberately *live* (non-blur-gated) validation, all real behavior this app already shipped and product-tested.
- **Rely on `wuik-change` for touched-gating** (fires only on an actual value diff): rejected once real-browser verification confirmed the risk the UI/UX expert flagged — a row focused and abandoned without ever being edited would show no invalid cue at all, worse than the pre-migration native-`blur` behavior.
- **Duplicate the wizard's "name required" message on both the field and the shared error line**: rejected after real-browser verification showed the exact same sentence rendered twice on screen — confusing, not reinforcing.
